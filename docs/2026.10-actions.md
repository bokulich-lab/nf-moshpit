# Pipeline updates after MOSHPIT 2026.7

This change adds the actions identified in the release audit: `types collate-contig-maps`, `mag bin-contigs-vamb`, `mag refine-bins-das-tool`, `annotate transfer-eggnog-annotations`, and `annotate estimate-tfa`, including the TFA explorer. Existing configurations keep their selected binner and annotation strategy. The new branches are opt-in.

## Run the new paths

Use a MOSHPIT environment or matching assembly/annotate/mag containers containing the post-2026.7 changes. A 2026.7 image does not provide these interfaces. VAMB and DAS Tool must be installed in the MAG environment. The new helper for deriving unbinned contigs also requires the assembly plugin in that environment, as the updated SemiBin2 pipeline does.

Start with a working `params.yml` based on `params.template.yml`, supplying reads, `runId`, environments/containers, and database cache/key addresses. Enable Kraken2, eggNOG ortholog/annotation databases and your chosen dereplication dependency. Either merge [the example settings](../examples/new-actions.yml) into your YAML or use this preset:

```bash
nextflow run main.nf -params-file params.yml -c conf/new-actions.config -profile singularity
```

Nextflow parameter files take precedence over config presets. Remove or update conflicting module settings in `params.yml`; merging the example YAML is the explicit alternative. The repository uses legacy Nextflow syntax; with Nextflow 26.10, set `NXF_SYNTAX_PARSER=v1`.

Use a fresh `runId` and output directory when moving to the updated environment. Existing `storeDir` marker files can skip tasks independently of `-resume`, and old SemiBin2 tasks lack its third output. Do not mix artifacts from different plugin versions in the same run cache.

## Configuration and outputs

- `binning.vamb.enabled` runs VAMB per sample. Its length/size thresholds and seed are in the template. `binning.primary` accepts `metabat2`, `semibin2`, `vamb`, or `das_tool`.
- `binning.das_tool.enabled` refines the **raw** results from every enabled binner before applying its own QC/filtering. Enable at least two binners. Inputs are ordered with their labels. Samples missing a result from any enabled binner are skipped with a warning; other samples continue. Refined bins enter the same QC, dereplication, classification and abundance paths as other bins.
- All binners collate their MAG/contig maps, bins and unbinned contigs. With `binning.fetchArtifact`, these QZAs are published. DAS Tool also publishes its summary and input-bin evaluation QZAs. Maps describe the original binning result before optional BUSCO filtering. VAMB/DAS Tool unbinned artifacts are derived from the corresponding per-sample bins. The derived map is imported from the MAG FASTA headers; the unbinned artifact records the public contig-filtering action in its provenance.
- SemiBin2 now saves its native `unbinned_contigs` output. BUSCO receives those sequences, replacing the previous fallback to every contig in the sample.
- `functional_annotation.transferFromContigs: true` requires `contigs` in annotation `enabledFor`. Contigs undergo the expensive eggNOG search/map once. Requested `mags` and `derep` targets receive annotations by matching their retained contig IDs; their separate searches are skipped. Destination sequences supply the mapping, so filtered MAGs cannot inherit a stale map. Keep this setting false to search each target independently.
- `functional_annotation.tfa.enabled` requires contig annotation/extraction, contig abundance, and Kraken2 contig classification. It uses the **per-contig** inventory, contig abundance, taxon-to-contig map and matching taxonomy. Each annotation type creates a TFA table, gene taxonomy artifact, and published interactive QZV linked from the pipeline report. `functional_annotation.tfa.fetchArtifact` publishes both QZAs. Optional `metadata` is passed to the explorer. This supplements the existing annotation abundance barplots.
- `genome_assembly.assembler: spades` exposes `spades.mode: meta|isolate|standard`. The existing `metaspades` name remains an alias for meta mode. Remove a legacy `--p-meta` from `spades.additionalFlags` when selecting another mode. QUAST reads `assembly_qc.quast` consistently with the template and stays disabled by default.

## Release checks still needed on real data

The pipeline preserves QIIME sample IDs and does not parse exported contig/BAM basenames. No filename rewrite is needed for the new plain names. Assembly #168 remains unmerged and is not assumed by this update.

The upstream SemiBin2 unbinned-ID issue from the audit is scoped away here by binning one sample per Nextflow task. Default assembler renaming also keeps contig IDs unique. This does not repair the upstream action when called on a multi-sample artifact outside this pipeline.

Run a representative dataset through the selected containers to validate biological bin recovery, resource requirements, DAS Tool scores and container startup. The automated workflow tests use a fake CLI for expensive binners and real small artifacts for annotation transfer, footerless extraction, TFA arithmetic and unbinned-contig generation; they do not establish VAMB/DAS Tool performance or biological correctness.

## Automated checks

```bash
python tests/run_smoke_tests.py
# In the updated MOSHPIT environment:
python -m pytest -q tests/test_artifacts.py
# Optional: save smoke commands and verify their flags against installed plugins.
NF_SMOKE_EVIDENCE=/tmp/nf-evidence python tests/run_smoke_tests.py
python tests/check_cli_contracts.py /tmp/nf-evidence/*.jsonl
```

`NEXTFLOW=/path/to/nextflow` selects a local executable. Smoke tests use isolated temporary output directories and exercise each primary binner, multi-binner refinement, missing bin results, BUSCO/filtering and two annotation types. They require Nextflow and Java, but no databases or containers.
